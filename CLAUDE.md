# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

This is a personal fork of [Quartz v5](https://quartz.jzhao.xyz/) (`jackyzha0/quartz`), the static-site generator that powers the French-language digital garden/blog at `www.shagshag.net`. The `content/` folder is an Obsidian vault mirror: notes are authored in Obsidian, marked `publish: true` in their frontmatter, and pushed here by the `quartz-syncer` Obsidian plugin. Pushes to this repo trigger a build+deploy on Sevalla — there is no separate manual deploy step. Treat `content/**/*.md` as synced/generated data rather than something to hand-edit unless the user asks.

Note: the parent directory (one level up from this repo) contains a stray duplicate `content/` folder left over from a file copy — it is not part of this project; the real content lives at `content/` inside this repo.

## Commands

```bash
npm ci                                    # install JS dependencies
npx quartz plugin install                 # install/sync community plugins into .quartz/plugins (from quartz.lock.json)
npx quartz plugin install --from-config   # sync installed plugins to match quartz.config.yaml (install missing, prune orphaned)
npx quartz build --serve                  # build + local dev server with hot reload (default http://localhost:8080)
npx quartz build                          # one-off production build into public/
npm run check                             # tsc --noEmit + prettier --check (run before considering a change done)
npm run format                            # prettier --write
npm test                                  # tsx --test (runs *.test.ts / *.test.js across quartz/ and installed plugins)
```

Run a single test file directly with `tsx --test path/to/file.test.ts`.

There is no lint script beyond `npm run check` (typecheck + prettier); there's no separate ESLint config.

### Plugin management (v5-specific)

Plugins are external Git repos, not local source — see "Plugin architecture" below.

```bash
npx quartz plugin list                          # installed plugins + versions
npx quartz plugin add github:org/repo           # install a plugin, adds it to quartz.config.yaml
npx quartz plugin add github:org/repo#branch    # pin to a branch/tag
npx quartz plugin remove <name>
npx quartz plugin enable <name> / disable <name> # toggle in quartz.config.yaml without uninstalling
npx quartz plugin config <name> --set key=value # edit a plugin's options in quartz.config.yaml
npx quartz plugin install --latest              # update all plugins to latest commits, respecting pinned refs
npx quartz plugin prune [--dry-run]             # remove plugins no longer referenced in quartz.config.yaml
npx quartz tui                                  # interactive plugin/layout manager
```

On low-memory machines, pass `--concurrency 1` (or `-c 1`) to `plugin install`/`plugin add` to avoid parallel clone/build OOMs.

## Architecture

### Repo layout

- `quartz/` — the Quartz engine (TypeScript, bundled with esbuild, JSX via Preact). This is framework code shared with upstream `jackyzha0/quartz`.
- `content/` — this site's Markdown content (the synced Obsidian vault). `content/développement/` and `content/projets/` are the main note folders; `content/medias/` holds attachments.
- `quartz.config.yaml` — site configuration and the declarative list of enabled community plugins (this is what's actually used at build time). `quartz.config.default.yaml` is the fallback used if `quartz.config.yaml` is absent.
- `quartz.ts` — thin entrypoint that calls `loadQuartzConfig()`/`loadQuartzLayout()`; only edit this for advanced overrides that can't be expressed in YAML (e.g. plugin options that take JS callbacks — see `docs/configuration.md`).
- `quartz.lock.json` — pinned commit hashes for every installed community plugin (analogous to a lockfile).
- `.quartz/plugins/` — gitignored; where community plugins are actually cloned and built. Re-generated by `npx quartz plugin install`.
- `docs/` — Quartz's own documentation, written as Quartz content itself. `npm run docs` (`npx quartz build --serve -d docs`) builds/serves *using `docs/` as the content directory* (`-d` is the input-directory flag, not output). Useful as the canonical reference for plugin options, layout, and CLI flags.
- `public/` — build output (gitignored equivalent; not source).

### Quartz v5 plugin system

This is the most important architectural difference from Quartz v4 and from most upstream Quartz documentation/tutorials you may know: **plugins are no longer hardcoded TypeScript arrays in `quartz.config.ts`.** Instead:

1. `quartz.config.yaml` under `plugins:` lists each plugin by Git `source` (typically `github:quartz-community/<name>`), whether it's `enabled`, its `order`, its `options`, and optionally a `layout` declaration (`position`, `priority`, `group`).
2. `quartz/plugins/loader/config-loader.ts` (`loadQuartzConfig()`) reads that YAML, clones/installs each enabled plugin into `.quartz/plugins/`, loads its manifest (from `package.json`'s `quartz` field or a `manifest.ts` export), validates inter-plugin dependencies, and categorizes each plugin by its declared `category` (`transformer`, `filter`, `emitter`, `pageType`, or `component`) — a single plugin can belong to multiple categories.
3. `loadQuartzLayout()` in the same file builds the page layout (which components render in `left`/`right`/`beforeBody`/`afterBody`) from the same YAML's `layout:` section and each plugin's `layout` declaration, resolving `group`s into flex containers and applying `display`/`condition` wrappers.
4. Plugins are cloned as standalone Git repos and built with `tsup`; most ship a pre-built `dist/`, so installs are normally fast.
5. Shared code between plugins comes from three community npm packages layered `@quartz-community/types` → `@quartz-community/utils` → `@quartz-community/runtime`; plugins depend on these, not on `quartz/` internals.

Only a handful of plugins remain built into `quartz/` itself (in `quartz/plugins/{emitters,filters,transformers,pageTypes}/`) — e.g. `ComponentResources`, `Assets`, `Static`, and the 404 page type. Everything else you see referenced in `quartz.config.yaml` (search, explorer, backlinks, table-of-contents, obsidian-flavored-markdown, etc.) is a separate `quartz-community/*` GitHub repo, cloned on demand.

When asked to change site behavior, check `quartz.config.yaml` first (enable/disable/reorder/configure a plugin, or adjust `layout:`) before reaching for code changes in `quartz/`. Code changes in `quartz/` affect the shared engine; changes to an individual plugin's behavior belong in that plugin's own repo (cloned under `.quartz/plugins/<name>/`, which is gitignored and not meant to be hand-edited in this repo).

### Build pipeline (content → HTML)

`quartz/build.ts` (invoked by `quartz/bootstrap-cli.mjs`, which also transpiles `quartz/` itself with esbuild): glob `content/` → parse each Markdown file into a vfile (`quartz/processors/parse.ts`, remark→rehype through unified, running transformer plugins' `markdownPlugins`/`htmlPlugins`/`textTransform`) → filter via filter plugins' `shouldPublish` (`quartz/processors/filter.ts`) → emit via emitter plugins' `emit`/`partialEmit` (`quartz/processors/emit.ts`), including the `PageTypeDispatcher` which routes each page to the matching page-type plugin's frame/body component and renders HAST→JSX (Preact)→HTML. In `--watch`/`--serve` mode this reruns incrementally per changed file with a 250ms debounce and pushes a WebSocket refresh to the browser. See `docs/advanced/architecture.md` for the full trace.

### Page frames

Distinct from plugins: a page's frame (`quartz/components/frames/`) controls the inner HTML skeleton (three-column `DefaultFrame`, `FullWidthFrame`, `MinimalFrame`, or a plugin-registered frame like `canvas-page`'s). Resolved per page type via `layout.byPageType.<type>.template` in YAML, else the page-type plugin's declared `frame`, else `"default"`.

## Content authoring conventions

- Frontmatter `publish: true` is what makes a note live (via the `quartz-syncer` sync from Obsidian, and again via the `remove-draft`/`explicit-publish` filter plugins at build time).
- Wikilinks (`[[Note Name]]`), callouts, and other Obsidian syntax are handled by the `obsidian-flavored-markdown` community plugin — see `quartz.config.yaml`'s `obsidian-flavored-markdown` entry for which features (comments, mermaid, tags, checkboxes, etc.) are on.
- Locale is `fr-FR`; most content is in French.
